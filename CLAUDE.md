# Cyrano: project brief

## Goal
Cyrano is a desktop CV generator written in Rust.
- The user creates named profiles holding their CV data. Data is encrypted on disk as soon as it is written.
- The user picks an HTML template from a folder, edits their data in a form, previews the rendered CV, and exports a PDF.
- Password-protected profiles prompt for the password before decrypting (3 attempts, then the prompt closes).
- Templates are discovered from a folder and are extensible: a folder with a `TEMPLATE.cyrano` TOML marker.
- Data is injected into the template with Tera. The HTML is converted to PDF through headless Chrome using the `mestra-core` crate.

## Workspace
Cargo workspace with two crates, plus vendored crates.
- `core/` (`cyrano-core`): pure business logic, no GUI dependency. The user owns it and writes it; **never modify it**.
- `gui/` (`cyrano-gui`): Dioxus 0.7 desktop app on the **native renderer (Blitz/WGPU/Vello), not a webview**.
- `gui/vendor/`: patched copies of `dioxus-native`, `anyrender_vello`, `blitz-dom`.
- Root `Cargo.toml` has `[patch.crates-io] blitz-dom = { path = "gui/vendor/blitz-dom" }`.

## Core (read only for the GUI side)
- Crypto: Argon2 key derivation, XChaCha20Poly1305. Key derived once at unlock and cached for the session.
- `profile::Store`: locked and unlocked maps keyed by profile dir. `create_profile`, `unlock_profile`, `lock_profile`, `delete_profile`. `UnlockedProfile` exposes `data()`, `data_mut()`, `save()`, `save_asset()`, `load_asset()`.
- Assets (for example `PROFILE_PICTURE`) are stored encrypted per profile. They are embedded into rendered HTML as base64 data URIs.
- `template::Store`: `Template { name, description, entry_path, required_assets: Vec<String-like Asset> }`. `Template::render(dir, &CvData, &[Asset]) -> RenderedTemplate`. `RenderedTemplate::to_pdf(output_dir)` is async and needs a Chromium binary on PATH.
- `CvData`: name, title, description, age, location, email, phonenumber, links, projects, experience, education, hard_skills, soft_skills, languages, hobbies. Dates are `DateRange { start: YearMonth, end: Option<YearMonth> }`, where year 0 means "no start date" in the GUI.
- Errors: one `thiserror` enum per module in a sibling `error.rs`.
- Scans return `Result<(Self, Vec<(PathBuf, Error)>), Error>`: tolerate bad items, report them as warnings.

## GUI architecture
- `main.rs`: custom launcher (`dioxus_native::launch_cfg`) with a transparent, undecorated window, window icon, Wayland app id `cyrano`.
- `state.rs`: `AppState` (Copy struct of Signals provided via context): preferences, template store, profile store, toast notices, screen navigation, maximized flag, current profile name (drives the window title), quit flushers.
- `preferences.rs`: lives in the GUI crate (moved out of core). TOML in the config dir: theme, profiles_dir, templates_dir, output_dir.
- `render.rs`: `preview()` renders the template, converts to PDF, rasterises with `hayro` to PNG data URIs. `export()` writes the PDF named `Person-Template.pdf`.
- `views/`: `shell` (header and persistent screens), `home` (template cards), `editor/` (workspace, session, preview pane, settings pane, profile picker, dialogs, CV form sections), `settings_dialog`.
- `components/`: Button, Card, Badge, Modal, Dropdown, Section, TextInput, TextArea, PasswordInput, Toasts, Logo, ThemeToggle, window controls and resize handles.
- Editor `Session` (Copy struct of Signals, provided via context): active profile, draft `CvData`, assets, preview state, dialog state, drag state. Autosave is a debounced `use_resource` (700 ms) plus a flush on quit.
- CV form: rows reorderable by drag and drop (built from mouse down/move/up, see below), add/remove buttons, string-list editors.

## Styling
- Tailwind v4, generated by `dx` into `gui/assets/tailwind.css` (tracked in git). All styling is Tailwind classes plus custom `@utility` rules in `gui/tailwind.css`.
- Light and dark themes through CSS variables (`--canvas`, `--surface`, `--ink`, `--accent` ...) switched by a `.dark` class on the root. Palette comes from the logo: cream `#f4eed7` and navy `#132135`, gold accent.
- Raleway font bundled in `assets/fonts` and loaded through `assets/fonts.css`.
- The root is rounded with transparent corners (premultiplied-alpha surface) and square when maximized.

## Blitz (native renderer) gotchas, all learned the hard way
- Tailwind `hover:` variants are wrapped in `@media (hover: hover)`, which Blitz never matches. Fixed with `@custom-variant hover (&:hover);`.
- CSS `transform` is applied to an element's box but **not to its text**. No scale or translate on text-bearing elements. Use glow, border, padding and opacity effects instead. Transform-origin vertical percent is resolved against width.
- Zero-width borders can paint as hairlines. Fixed with `border-color: transparent` by default.
- `animation-fill-mode: both` keeps animations active forever, forcing continuous redraw and a memory leak. Use `backwards`. Avoid infinite animations.
- Transitions of inherited `color` on every element lag. Transition `color` only on the root and on elements with an explicit text color class.
- `<input>`/`<textarea>`: no `placeholder`, no password masking, no text wrapping, and the text font ignores CSS font-family.
  - Placeholders and password masks are overlays under the input (`-z-10`, input `relative z-10`) because absolute elements are hit-tested first and `pointer-events` is ignored.
  - Wrapping of single and multi-line inputs is a patch in `vendor/blitz-dom` (editor width is set from the layout width).
- Hit-testing bug with scrolled containers capturing clicks above them: patched in vendored `blitz-dom`.
- Events available: mousedown, mousemove, mouseup, click, key events, input. No mouseenter, drag events, wheel events or mounted rects. Hover logic uses CSS, drag reorder uses mousemove over rows.
- Replacing a large screen subtree corrupts Blitz's node bookkeeping (stale ElementId mapping). So screens stay mounted and are hidden with `display:none`; there is no router, navigation is state-based.
- `position: fixed` inside an `overflow` container is clipped to it. Dialogs are rendered at the workspace or shell root.
- Plain block parents with flex children can lay children out at stale widths. Prefer flex or grid containers.
- Rotated bars rendered wrongly, so icons that need diagonals (close X, password eye) are inline SVG with `stroke="currentColor"`.
- Wheel scrolling is eased in the vendored `dioxus-native` (56 px per notch, 20 percent easing per frame).
- Window decorations are custom: the vendored `dioxus-native` exposes the winit `Arc<Window>` through context, used for drag, resize handles, minimize, maximize (icon tracks state by polling) and close.
- Wayland ignores winit window icons. The icon comes from a `.desktop` file: `gui/assets/cyrano.desktop` and `gui/scripts/install-desktop-entry.sh`.
- Clipboard paste on Wayland needs `arboard` with `wayland-data-control`.

## Working rules with this user
- The user writes core code; do not edit `core/`. Root files only when asked.
- Commits go on `feat/gui`: small (about 150 lines max), one-line messages, no co-author or "generated by" lines, never push or touch branches.
- No code comments or docs. Idiomatic Dioxus, Tailwind only, extract components.
- Verification uses an isolated virtual KWin compositor with a scratch `XDG_DATA_HOME`/`XDG_CONFIG_HOME`, never the user's real screen.
- User is French-speaking and does not like em dashes in text.

## Known limits and open items
- Memory still grows slowly with heavy use (previews leave Blitz image nodes until their ids are reused).
- Text caret is painted black, hard to see in dark mode.
- Input text always uses the system font.
- Date formatting ("Aujourd'hui", "-") lives in the user's templates under `~/.local/share/cyrano/templates/`, not in the app.
- Debug builds are slow for Argon2 and PDF rasterisation; use `dx serve --release` for real use.
